# 架构说明

应用使用原生 ArkTS / ArkUI，推理在设备本地完成；后端负责结构化识别记录和模型分发。

1. `services/ImageFiles.ets` 将相册 URI 复制为沙箱 JPEG，处理方向并生成缩略图。
2. `inference/DetectionWorker.ets` 在 TaskPool 读取和解码图片；`Vision.ts` 实现 letterbox、RGB/NCHW、归一化、YOLO 输出解码及分类 NMS。
3. `entry/src/main/cpp/detector.cpp` 通过 N-API 接收张量，使用 dlopen/dlsym 加载 ORT 1.16.3 CPU 运行库，校验模型契约并串行保护 session 缓存。
4. `pages/Index.ets` 展示检测框与类别，支持人工修订；`data/Records.ets` 使用 RDB 事务保存版本快照和持久化 Outbox。
5. `services/Cloud.ets` 处理 JWT 刷新、401 重放和重试退避。后端 `backend/app.py` 从已验证 JWT 推导设备归属，以 recordId/revision 实现幂等同步及冲突保护。
6. `services/Models.ets` 下载模型、校验 SHA256、试加载后切换指针，保留旧版本用于回退。相机入口单独位于 `services/CameraService.ets`。

端侧保留图片，云端仅保存结构化结果；所有设备凭据由本地命令显式登记，不开放 HTTP 自助登记。数据库和日志默认持久化在 `backend/data/`。
