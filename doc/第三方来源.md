## 鸿蒙运行库

使用 <https://github.com/csukuangfj/onnxruntime-libs/releases/tag/v1.16.3>：

- `onnxruntime-ohos-x86_64-1.16.3.zip`
- `onnxruntime-ohos-arm64-v8a-1.16.3.zip`

包内 libonnxruntime.so 位于 `SmartItemAssistant/entry/libs/<ABI>/`，构建使用的 C API 头文件在 `native/onnxruntime/<ABI>/include/`，`ORT_API_VERSION=16`。公开仓库只保留实际使用的头文件和一份运行库，不收录开发时残留的其他版本头文件。许可证为 MIT，保留 `ONNX-Runtime-LICENSE` 与 `ONNX-Runtime-ThirdPartyNotices.txt`。`doc/evidence/dependencies.json` 记录最终文件哈希和开发环境版本。

选择1.16.3的依据是本次API26模拟器实际加载和推理结果。较新OHOS构建1.30及1.28.2在此环境的动态加载阶段崩溃，不能仅因版本较新就替换。Native封装自行编写，通过dlopen/dlsym加载，避免直接符号解析问题；模型运行用CPU，两条intra-op线程。

## 重新导出模型（可选）

日常构建直接使用已包含的 ONNX，无需安装 PyTorch。若要重新导出，在仓库根目录创建独立 Python 3.12 环境并安装上游依赖（具体版本见 dependencies.json），然后：

```powershell
git clone https://github.com/iMoonLab/yolov13.git .work/yolov13-upstream
git -C .work/yolov13-upstream checkout 73289949533efac82bb5f72ec19b746618656bd2
Invoke-WebRequest https://github.com/iMoonLab/yolov13/releases/download/yolov13/yolov13n.pt -OutFile models/yolov13n.pt
# 在配置好的导出环境中执行，脚本校验 checkpoint 哈希并对照 PyTorch/ORT：
python scripts/export_model.py
```

导出后需同时更新 App 的 `resources/rawfile/` 中模型与 manifest，再构建 App。服务端仍使用 `models/`，两处副本分别用于端侧离线启动与服务端模型分发。上游源码和权重原件不重复收录，使用上述固定链接获取。
